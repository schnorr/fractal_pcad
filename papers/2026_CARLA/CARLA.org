*** Context                                                        :ignore:
Modern computing is inherently parallel. From multi-core processors in
everyday devices to the hundreds of thousands of cores in
leadership-class supercomputers, parallelism is no longer an advanced
specialization: it is the default execution model. Nevertheless,
despite this reality, parallel computational thinking remains a
late-stage topic in most Computer Science curricula. Concepts such as
domain partitioning, task granularity, load balancing, speedup, and
scalability are routinely deferred to upper-division or graduate
electives, leaving students ill-equipped to reason about the hardware
they will inevitably program. This curricular gap begins even earlier:
prospective students arriving from high school have virtually no
exposure to parallel computational thinking, entering undergraduate
programs without even an informal intuition for the concepts that
professors will address years into the students' studies. This
situation is particularly consequential in the context of
High-Performance Computing (HPC), where understanding the interplay
between problem decomposition and machine architecture is a
prerequisite for productive scientific work.

A well-established strategy for bridging this gap is the use of
interactive, visually rich tools that make parallel phenomena
tangible. When a student can directly observe how domain partitioning
affects load balance, or watch speedup curves shift in response to
granularity choices, abstract concepts acquire intuitive
grounding. However, tools designed with this pedagogical goal in mind
are scarce. Existing HPC education frameworks assume prior programming
experience, offer limited real-time visual feedback, or present
architectures too complex to be useful in introductory settings.

*** Bridge to our strategy                                         :ignore:

This context motivated the development of two open-source applications
at the Universidade Federal do Rio Grande do Sul (UFRGS). The
immediate driver was a concrete pedagogical event: the annual Open Day
at UFRGS, which welcomes prospective students, mostly high schoolers
with no formal computing background, for a first hands-on encounter
with Computer Science. This setting imposed strict design
constraints. The tools had to be immediately accessible, visually
compelling, and capable of conveying non-trivial parallel-computing
concepts during a brief, informal interaction. At the same time, the
same tools should scale in depth, remaining useful in formal
undergraduate instruction.

*** The two applications overview                                  :ignore:

The two selected problems are visually compelling, computationally
intensive, and pedagogically complementary. The first is the
Mandelbrot set, a canonical embarrassingly parallel problem. Each
pixel's computation is independent, making it an ideal entry point for
introducing domain decomposition and granularity without the cognitive
overhead of inter-process communication. Its visual richness is a key
asset: zooming in increases the resolution demands and redistributes
computational work across regions, allowing users to observe and
address load imbalance directly. The second application is an N-Body
gravitational simulation (galaxy simulation), which presents a
fundamentally different parallel structure. With O(N²) complexity and
mandatory communication phases between computation steps, it exposes
students to the challenges of tightly coupled parallelism:
synchronization, communication overhead, and the tension between
scalability and correctness. Together, the two problems span a
representative spectrum of parallel computing, from trivially
decomposable to communication-bound, with a visual interactive
framework.

The rendering and simulation processes thus become live experiments in
parallel computational thinking. Rather than reasoning about
parallelism through code inspection alone, users observe its effects
directly: partition granularity across the Mandelbrot canvas, particle
mappings for workers evolving under gravitational interaction, and
simulation speed responding to changes in process count and
granularity. Core concepts, such as domain decomposition, granularity,
load balance, speedup, efficiency, and scalability, emerge naturally
from interaction, grounded in immediate visual feedback.

*** Contribution Wrap-up                                           :ignore:

The main contributions of this work are as follows:
- Two open-source interactive tools for parallel computing education,
  built on an MPI-based architecture with real-time visualization;
- An explicit conceptual mapping between the interactive and visual
  elements of both tools and the core concepts of parallel
  computational thinking, namely domain partitioning, granularity,
  load balance, speedup, efficiency, and scalability;
- A pedagogical experience report covering two distinct audiences —

*** Parallel Applications Design

**** Common Client/Server Design

Both applications share a common client–server architecture, in which a graphical
client and an MPI-based server run as separate processes, communicating over
a TCP connection. The client is a lightweight application running on a local
machine that simply requests work from the coordinator based on user input.
Meanwhile, the server is a distributed MPI application executing on a dedicated
cluster, taking responsibility for domain decomposition, process synchronization, and
the relevant numerical calculations. This distinction is important, as it gives users
a tangible sense that their interactions are dispatching work to a larger
computational system.

**** Mandelbrot Set

***** TODO [cite sscad fractal paper?]                           :ignore:

The Mandelbrot Set cite:mandelbrot1980 is a well-known compute-bound
application that is considered embarrassingly parallel. It consists of
iteratively applying the complex function $f(z) = z^2 + c$, starting
from $z=0$. The complex number $c$ belongs to the Mandelbrot set if
its value does not exceed a fixed radius before an iteration limit is
reached.  The Mandelbrot Set is commonly visualized by mapping points
on the 2D plane of the screen to points $c$ on the complex plane, with
each point representing a pixel colored by the number of iterations
until the point escapes.

While all points can be computed independently, different points
require a varying number of iterations to compute before escaping, and
as such, the application shows a highly irregular workload. This
irregularity, as well as the intuitive visualization, makes the
Mandelbrot Set an ideal pedagogical tool for introducing students to
the concepts of load distribution and dynamic load balancing.

***** Architecture

The Mandelbrot server relies on a demand-driven load balancer designed
around a coordinator-worker model. The coordinator (MPI rank 0)
receives the user's rendering request and discretizes the fractal
space into smaller payloads based on a specified
\textit{granularity}. The granularity parameter dictates the size of
the square blocks the workload is partitioned into for workers.

A pool of MPI workers actively request work from the coordinator.
Once a worker finishes calculating the numerical depths for its
assigned block, it returns the response to the coordinator and
requests a new set of points.  This dynamic distribution ensures that
computationally light regions do not cause workers to idle while
others are stuck processing dense regions.

***** Client

The graphical client is designed to be interactive and responsive, allowing
users to select color scheme, set configurations such as granularity
and select regions to zoom across the complex plane via mouse and
keyboard. It operates using threads to handle TCP communication and UI
rendering simultaneously.

Crucially, the coordinator delivers results back to the client block
by block. As these responses arrive asynchronously, the client applies
a coloring function and incrementally updates a shared pixel
buffer. When users zoom into computationally dense fractal regions,
they visually perceive load imbalance in real time, as the "easy"
blocks render almost instantaneously, while the "hard" blocks stall as
the worker nodes process them. Additionally, there is an option to
overlay a unique color for each block based on the worker id, allowing
users to visualize which workers computed which regions of the
fractal, as exemplify Figure @@latex:\ref{fig:workers}@@.

**** N-Body Simulation
  The N-Body gravitational simulation is a classical problem in
  computational physics in which $N$ bodies interact pairwise through
  Newtonian gravity. At each time step, the gravitational acceleration
  acting on body $i$ is computed by summing the contributions of all
  other $N-1$ bodies: $$\mathbf{a}i = \sum{j \neq i} \frac{G ,
  m_j}{|\mathbf{r}{ij}|^2 + \epsilon^2} \hat{\mathbf{r}}{ij}$$ where $G$ is
  the gravitational constant, $m_j$ is the mass of body $j$,
  $\mathbf{r}_{ij}$ is the displacement vector from $i$ to $j$, and $\epsilon$
  is a softening length that prevents force singularities at close
  range. This sum must be done for every body, having an inherent
  $O(N^2)$ computational complexity per step. Our application
  instantiates this problem as a galaxy simulation, where particles
  orbit a central black hole. Unlike the Mandelbrot set, where each pixel can be
  computed by itself, the N-Body problem is tightly coupled: computing
  the forces on any body requires the current positions of every other
  body. This coupling makes it impossible to decompose the problem
  into independent tasks and makes communication a important concern
  in any parallel implementation. The simulation therefore presents a
  complementary set of parallel computing concepts to the Mandelbrot
  application: rather than dynamic load balancing of independent work,
  we introduce a parallel problem with static load balancing
  constrained by synchronization barriers and communication.

***** Architecture

The N-Body simulation server adopts a different parallel model that
reflects the tightly coupled nature of gravitational
computation. Rather than a demand-driven coordinator-worker split, all
MPI ranks participate equally in the computation. The N particles are
statically partitioned into equal slices across all ranks, and each
rank computes the gravitational forces on its own slice. Since every
particle interacts with every other, each rank must read the full
particle array at every step. After each iteration, the workers
exchanges information through collective operations about the updated
positions, ensuring every process holds the complete system state
before the next step begins. Rank 0 additionally manages TCP
networking, receiving simulation requests from the client and
forwarding per-iteration results back as a stream of responses.

***** Client

The graphical client provides an interactive real-time view of the galaxy
simulation, where users can start new simulations, adjust the number
of particles and navigate the scene by zooming and panning with the
mouse. Particle positions are updated on screen as responses stream in
from the server, producing a smooth animation of the galaxy evolving
under gravity. Users can also switch the coloring mode to highlight
which MPI process computed each particle, making the domain partition
across workers directly visible.
